01 System Information

SQL Server exposes a rich set of built-in functions and dynamic management views (DMVs) that let you query the current state of the server, database, and session. These are the first tools to reach for when diagnosing an environment.

🖥️ Server-Level Functions

T-SQL 
-- Current SQL Server version and edition
SELECT @@VERSION                        -- full build string
SELECT SERVERPROPERTY('ProductVersion')  -- e.g. 16.0.4003.1
SELECT SERVERPROPERTY('Edition')         -- Developer / Standard / Enterprise
SELECT SERVERPROPERTY('InstanceName')    -- NULL = default instance
SELECT SERVERPROPERTY('Collation')       -- server collation

-- Active database context
SELECT DB_NAME()     -- current database
SELECT USER_NAME()   -- current database user
SELECT SUSER_NAME() -- current login name
SELECT @@SERVERNAME -- server\instance name

⚙️ Database-Level Properties

T-SQL 
-- All databases on the server
SELECT name, database_id, create_date,
       compatibility_level, collation_name,
       state_desc, recovery_model_desc
FROM   sys.databases
ORDER BY name;

-- Database-level property (single value)
SELECT DATABASEPROPERTYEX(DB_NAME(), 'Status')     -- ONLINE / OFFLINE
SELECT DATABASEPROPERTYEX(DB_NAME(), 'Recovery')   -- FULL / SIMPLE
SELECT DATABASEPROPERTYEX(DB_NAME(), 'Collation')  -- DB collation
💡
Tip — Compatibility Level

The compatibility_level in sys.databases controls which T-SQL features and query-optimizer behaviours are active. It does not have to match the installed SQL Server version — teams often keep it lower for safe upgrades.

02 System Catalog Views

Catalog views are the primary metadata API in SQL Server. Every object — table, view, procedure, trigger, index, constraint — has an entry in the sys schema. They are read-only and transactionally consistent.

Object Catalog
  • sys.objects — all objects
  • sys.tables — user tables
  • sys.views — views
  • sys.procedures — stored procs
  • sys.triggers — DDL & DML triggers
  • sys.synonyms — synonyms
Column & Type Catalog
  • sys.columns — all columns
  • sys.types — data types
  • sys.computed_columns
  • sys.identity_columns
  • sys.default_constraints
  • sys.check_constraints
Keys & Indexes
  • sys.indexes
  • sys.index_columns
  • sys.key_constraints
  • sys.foreign_keys
  • sys.foreign_key_columns
  • sys.stats
Schema & Security
  • sys.schemas
  • sys.principals
  • sys.database_permissions
  • sys.server_principals
  • sys.database_role_members
T-SQL — Catalog Quick Queries 
-- List every user-created object with its type
SELECT o.name, o.type_desc, s.name AS schema_name,
       o.create_date, o.modify_date
FROM   sys.objects o
JOIN   sys.schemas s ON s.schema_id = o.schema_id
WHERE  o.is_ms_shipped = 0
ORDER BY o.type_desc, o.name;
ℹ️
INFORMATION_SCHEMA vs sys.*

SQL Server also exposes ANSI-standard INFORMATION_SCHEMA views (e.g. INFORMATION_SCHEMA.TABLES, INFORMATION_SCHEMA.COLUMNS). They are portable across RDBMS vendors but contain less detail than sys.*. Prefer sys.* for SQL Server-specific work.

03 Trigger Metadata

Triggers are stored as first-class objects. Their metadata is split between sys.triggers (DML triggers), sys.server_triggers (server-scope DDL triggers), and sys.trigger_events which records which events activate each trigger.

🔍 Querying Trigger Metadata

T-SQL 
-- All DML triggers in the current database
SELECT
    t.name                                         AS trigger_name,
    OBJECT_NAME(t.parent_id)                       AS parent_table,
    t.type_desc,
    t.is_disabled,
    t.is_instead_of_trigger,
    t.create_date,
    t.modify_date,
    OBJECT_DEFINITION(t.object_id)                AS trigger_definition
FROM   sys.triggers t
WHERE  t.parent_class = 1   -- 1 = OBJECT_OR_COLUMN (DML)
ORDER BY parent_table, trigger_name;

-- Trigger events (INSERT / UPDATE / DELETE)
SELECT
    OBJECT_NAME(te.object_id) AS trigger_name,
    te.type_desc               AS event_type
FROM   sys.trigger_events te
ORDER BY trigger_name;

-- DDL triggers (database-scope)
SELECT name, type_desc, is_disabled, create_date
FROM   sys.triggers
WHERE  parent_class = 0;  -- 0 = DATABASE
ColumnTypeMeaning

04 Trigger Code & Examples

AFTER INSERT Trigger — Audit Log

T-SQL — DML Trigger 
CREATE OR ALTER TRIGGER dbo.trg_Orders_AfterInsert
ON  dbo.Orders
AFTER INSERT
AS
BEGIN
    SET NOCOUNT ON;

    INSERT INTO dbo.AuditLog (TableName, ActionType, RecordID, ChangedBy, ChangedAt)
    SELECT 'Orders', 'INSERT', i.OrderID, SUSER_NAME(), GETDATE()
    FROM inserted i;
END;
GO

INSTEAD OF DELETE Trigger — Soft Delete

T-SQL — INSTEAD OF Trigger 
CREATE OR ALTER TRIGGER dbo.trg_Employees_SoftDelete
ON  dbo.Employees
INSTEAD OF DELETE
AS
BEGIN
    SET NOCOUNT ON;

    UPDATE dbo.Employees
    SET    IsDeleted  = 1,
           DeletedAt  = GETDATE(),
           DeletedBy  = SUSER_NAME()
    WHERE  EmployeeID IN (SELECT EmployeeID FROM deleted);
END;
GO

DDL Trigger — Prevent Table Drops

T-SQL — DDL Trigger 
CREATE OR ALTER TRIGGER safety_NoDrop
ON  DATABASE
FOR DROP_TABLE, ALTER_TABLE
AS
BEGIN
    RAISERROR('DDL changes on tables are blocked. Contact the DBA.', 16, 1);
    ROLLBACK;
END;
GO

-- Disable / Enable trigger
DISABLE TRIGGER safety_NoDrop ON DATABASE;
ENABLE  TRIGGER safety_NoDrop ON DATABASE;
⚠️
Nested & Recursive Triggers

SQL Server allows triggers to fire other triggers (nesting up to 32 levels). Check @@NESTLEVEL inside trigger code if you need to guard against recursion. Server-level setting nested triggers can disable this globally.

05 Tables Metadata

📋 Listing Tables & Their Properties

T-SQL 
-- All user tables with row count and size
SELECT
    s.name            AS schema_name,
    t.name            AS table_name,
    t.create_date,
    t.modify_date,
    p.rows            AS row_count,
    SUM(a.total_pages) * 8 AS total_kb
FROM       sys.tables           t
JOIN       sys.schemas          s  ON s.schema_id     = t.schema_id
JOIN       sys.indexes          i  ON i.object_id     = t.object_id AND i.index_id < 2
JOIN       sys.partitions       p  ON p.object_id     = i.object_id AND p.index_id  = i.index_id
JOIN       sys.allocation_units a  ON a.container_id  = p.partition_id
GROUP BY   s.name, t.name, t.create_date, t.modify_date, p.rows
ORDER BY   total_kb DESC;

🧱 Column-Level Metadata

T-SQL 
-- Full column details for a specific table
SELECT
    c.column_id,
    c.name                     AS column_name,
    tp.name                    AS data_type,
    c.max_length,
    c.precision,
    c.scale,
    c.is_nullable,
    c.is_identity,
    c.is_computed,
    OBJECT_DEFINITION(c.default_object_id) AS default_value
FROM   sys.columns c
JOIN   sys.types   tp ON tp.user_type_id = c.user_type_id
WHERE  c.object_id = OBJECT_ID(N'dbo.Orders')
ORDER BY c.column_id;

🔑 Primary Keys, Foreign Keys & Indexes

T-SQL 
-- Primary key columns
SELECT kc.name AS pk_name, c.name AS column_name
FROM   sys.key_constraints kc
JOIN   sys.index_columns   ic ON ic.object_id = kc.parent_object_id
                                AND ic.index_id  = kc.unique_index_id
JOIN   sys.columns         c  ON c.object_id  = ic.object_id
                                AND c.column_id  = ic.column_id
WHERE  kc.type = 'PK'
AND    kc.parent_object_id = OBJECT_ID(N'dbo.Orders');

-- Foreign key relationships
SELECT
    fk.name                               AS fk_name,
    OBJECT_NAME(fk.parent_object_id)     AS child_table,
    cp.name                               AS child_column,
    OBJECT_NAME(fk.referenced_object_id) AS parent_table,
    rp.name                               AS parent_column,
    fk.delete_referential_action_desc,
    fk.update_referential_action_desc
FROM  sys.foreign_keys        fk
JOIN  sys.foreign_key_columns fc ON fc.constraint_object_id = fk.object_id
JOIN  sys.columns             cp ON cp.object_id = fc.parent_object_id
                               AND cp.column_id = fc.parent_column_id
JOIN  sys.columns             rp ON rp.object_id = fc.referenced_object_id
                               AND rp.column_id = fc.referenced_column_id
ORDER BY child_table, fk_name;

06 Schema Metadata

A schema is a namespace container for database objects. Beyond the default dbo, production databases typically use schemas to group objects by domain, team ownership, or security boundary.

📂 Listing Schemas

T-SQL 
-- All schemas and their owners
SELECT
    s.schema_id,
    s.name              AS schema_name,
    dp.name             AS owner,
    dp.type_desc        AS owner_type
FROM   sys.schemas    s
JOIN   sys.principals dp ON dp.principal_id = s.principal_id
ORDER BY s.name;

-- Count of objects per schema
SELECT
    s.name            AS schema_name,
    o.type_desc,
    COUNT(*)          AS object_count
FROM   sys.objects o
JOIN   sys.schemas s ON s.schema_id = o.schema_id
WHERE  o.is_ms_shipped = 0
GROUP BY s.name, o.type_desc
ORDER BY s.name, o.type_desc;

🏗️ Create & Transfer Schema

T-SQL — DDL 
-- Create a new schema owned by a specific user
CREATE SCHEMA Sales AUTHORIZATION dbo;
GO

-- Move a table to a different schema
ALTER SCHEMA Sales TRANSFER dbo.Orders;
GO

-- Change schema owner
ALTER AUTHORIZATION ON SCHEMA::Sales TO SalesUser;
GO
✅
Schema Best Practice

Never put objects directly into the guest or sys schemas. Use domain schemas (e.g. Sales, HR, Finance) to clarify ownership and simplify permission grants — GRANT SELECT ON SCHEMA::Sales TO ReportReader.

07 Stored Procedure Metadata

📜 Listing & Inspecting Procedures

T-SQL 
-- All stored procedures with schema and dates
SELECT
    s.name          AS schema_name,
    p.name          AS procedure_name,
    p.create_date,
    p.modify_date,
    p.is_ms_shipped
FROM   sys.procedures p
JOIN   sys.schemas    s ON s.schema_id = p.schema_id
WHERE  p.is_ms_shipped = 0
ORDER BY s.name, p.name;

-- Retrieve procedure source code
SELECT OBJECT_DEFINITION(OBJECT_ID(N'dbo.usp_GetOrders'));

-- Parameters of a stored procedure
SELECT
    pm.name         AS param_name,
    tp.name         AS data_type,
    pm.max_length,
    pm.is_output,
    pm.has_default_value,
    pm.default_value
FROM   sys.parameters pm
JOIN   sys.types      tp ON tp.user_type_id = pm.user_type_id
WHERE  pm.object_id = OBJECT_ID(N'dbo.usp_GetOrders')
ORDER BY pm.parameter_id;

08 Rename Operations

All renaming in SQL Server goes through sp_rename. It updates the name in sys.objects (or sys.columns, sys.indexes) but does not update references inside other objects — views, procedures, and triggers that reference the old name will break until you fix them.

✏️ Renaming Syntax Reference

T-SQL — sp_rename 
-- Rename a TABLE
EXEC sp_rename
    @objname  = N'dbo.OldTableName',
    @newname  = N'NewTableName',
    @objtype  = N'OBJECT';

-- Rename a COLUMN
EXEC sp_rename
    @objname  = N'dbo.Customers.Fname',  -- table.column format
    @newname  = N'FirstName',
    @objtype  = N'COLUMN';

-- Rename an INDEX
EXEC sp_rename
    @objname  = N'dbo.Orders.IX_Orders_CustomerID',
    @newname  = N'IX_Orders_CustID',
    @objtype  = N'INDEX';

-- Rename a STORED PROCEDURE
EXEC sp_rename
    @objname  = N'dbo.usp_GetOldName',
    @newname  = N'usp_GetNewName';

-- Move table to a different schema (uses ALTER, not sp_rename)
ALTER SCHEMA NewSchema TRANSFER OldSchema.TableName;
🚨
After Any Rename — Refresh Dependent Objects

Run EXEC sp_refreshview 'dbo.YourView' for views, and use sys.sql_expression_dependencies to locate all objects referencing the renamed item. Rebuild those with CREATE OR ALTER. Failure to do so results in silent runtime errors.

🔗 Finding Dependencies Before Rename

T-SQL 
-- Objects that reference dbo.Orders
SELECT
    OBJECT_NAME(sed.referencing_id) AS referencing_object,
    o.type_desc
FROM   sys.sql_expression_dependencies sed
JOIN   sys.objects o ON o.object_id = sed.referencing_id
WHERE  sed.referenced_entity_name = N'Orders'
AND    sed.referenced_schema_name = N'dbo';

09 Finding Metadata Objects

When you inherit a database or debug an issue, you need ways to quickly locate objects by name, column name, content in source code, or dependency chain.

🔎 Search by Object Name

T-SQL 
-- Find any object whose name contains a keyword
SELECT
    s.name      AS schema_name,
    o.name      AS object_name,
    o.type_desc,
    o.create_date
FROM   sys.objects o
JOIN   sys.schemas s ON s.schema_id = o.schema_id
WHERE  o.name LIKE N'%Order%'
AND    o.is_ms_shipped = 0
ORDER BY o.type_desc, o.name;

🔎 Search by Column Name Across All Tables

T-SQL 
SELECT
    OBJECT_SCHEMA_NAME(c.object_id) AS schema_name,
    OBJECT_NAME(c.object_id)        AS table_name,
    c.name                           AS column_name,
    tp.name                          AS data_type
FROM   sys.columns c
JOIN   sys.types   tp ON tp.user_type_id = c.user_type_id
WHERE  c.name LIKE N'%CustomerID%'
ORDER BY table_name, column_name;

🔎 Search Inside Source Code (Procedures, Views, Triggers)

T-SQL 
-- Search object definitions for a keyword
SELECT
    o.type_desc,
    s.name  AS schema_name,
    o.name  AS object_name,
    sm.definition
FROM   sys.sql_modules sm
JOIN   sys.objects     o  ON o.object_id  = sm.object_id
JOIN   sys.schemas     s  ON s.schema_id  = o.schema_id
WHERE  sm.definition  LIKE N'%SearchKeyword%'
ORDER BY o.type_desc, o.name;
💡
OBJECT_ID / OBJECT_NAME Shorthand

Use OBJECT_ID(N'schema.object') to check existence — it returns NULL if not found. Combine with IF OBJECT_ID(...) IS NOT NULL for safe drops or conditional DDL.

10 Solving Metadata Issues

🛠️ Common Problems & Fixes

ProblemSymptomSolution
Stale View Metadata Column count/type mismatch after table change EXEC sp_refreshview 'dbo.YourView' or CREATE OR ALTER VIEW
Broken Dependencies Proc/trigger errors after rename or drop Query sys.sql_expression_dependencies, then CREATE OR ALTER affected objects
Orphaned Schemas DROP SCHEMA fails — schema has objects Transfer all objects: ALTER SCHEMA dbo TRANSFER OldSchema.Obj, then drop
Disabled Triggers Expected side-effects not happening Check sys.triggers WHERE is_disabled = 1, then ENABLE TRIGGER
Ghost Constraints Cannot drop column — FK/CHECK still present Query sys.foreign_keys / sys.check_constraints, drop constraints first
Encrypted Object sp_helptext returns "encrypted" message Use DAC connection or third-party tools; avoid WITH ENCRYPTION for critical objects
Statistics Out of Date Bad query plans, unexpected full scans UPDATE STATISTICS dbo.TableName WITH FULLSCAN
Missing Index Metadata Slow queries, DMV suggestions ignored Query sys.dm_db_missing_index_details and sys.dm_db_missing_index_group_stats

🩺 Refresh All Views in a Database

T-SQL — Cursor Loop 
DECLARE @vname NVARCHAR(512);
DECLARE cur CURSOR FOR
    SELECT QUOTENAME(s.name) + '.' + QUOTENAME(v.name)
    FROM   sys.views v
    JOIN   sys.schemas s ON s.schema_id = v.schema_id;

OPEN cur;
FETCH NEXT FROM cur INTO @vname;
WHILE @@FETCH_STATUS = 0
BEGIN
    BEGIN TRY
        EXEC sp_refreshview @vname;
    END TRY
    BEGIN CATCH
        PRINT 'Failed: ' + @vname + ' — ' + ERROR_MESSAGE();
    END CATCH
    FETCH NEXT FROM cur INTO @vname;
END
CLOSE cur; DEALLOCATE cur;

🔍 Detect Invalid / Broken Objects

T-SQL 
-- OBJECT_DEFINITION returns NULL for encrypted or missing objects
SELECT
    s.name  AS schema_name,
    o.name  AS object_name,
    o.type_desc
FROM   sys.sql_modules sm
JOIN   sys.objects     o  ON o.object_id = sm.object_id
JOIN   sys.schemas     s  ON s.schema_id = o.schema_id
WHERE  sm.is_recompiled = 1
   OR  OBJECT_DEFINITION(o.object_id) IS NULL;
